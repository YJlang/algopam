# [알고팜 3주차] 프로그래머스 멀리 뛰기 - 마지막 한 칸만 생각하면 피보나치가 보인다

제출은 통과했는데 정작 **"이 코드가 왜 맞는지"**를 설명하지 못했던 문제다. 점화식 `f(n) = f(n-1) + f(n-2)`를 외워서 쓰긴 했지만 *왜* 앞 두 개의 합인지, 그리고 `a, b = b, a+b` 같은 동시대입이 *왜* 안 깨지는지 몰랐다. 이번에 "마지막 점프 한 번"만 따로 떼서 생각하니 전부 풀렸다.

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12914

## 문제 정보

- 분류: 동적 계획법(DP) — 점화식으로 푸는 전형적인 피보나치형 문제
- 제한: `n`은 **1 이상 2000 이하** 정수
- 출력: 방법의 수를 **`1234567`로 나눈 나머지**
- 시간/메모리 제한: 프로그래머스 페이지에 별도 표기 없음 (DP `O(n)`이면 충분히 통과)

## 문제 설명

효진이는 한 번에 **1칸 또는 2칸**을 뛸 수 있다. 칸이 `n`개 있을 때 맨 끝 칸에 정확히 도달하는 **서로 다른 방법의 수**를 구한다. 순서가 다르면 다른 방법으로 센다 (`1+1+2`와 `2+1+1`은 별개).

포장을 벗기면 결국 이 질문이다:

> **1과 2를 여러 번 더해서 합이 `n`이 되게 만드는 순서가 몇 가지인가?**

## 입력 형식

- 정수 `n` (1 ≤ `n` ≤ 2000)

## 출력 형식

- 끝 칸에 도달하는 방법의 수를 `1234567`로 나눈 나머지(정수)

## 예제 입력 1

```text
4
```

## 예제 출력 1

```text
5
```

`n = 4`일 때 직접 나열하면:

```text
1 + 1 + 1 + 1
1 + 1 + 2
1 + 2 + 1
2 + 1 + 1
2 + 2
```

→ 5가지.

## 예제 입력 2

```text
3
```

## 예제 출력 2

```text
3
```

`(1,1,1) / (1,2) / (2,1)` → 3가지.

## 접근 아이디어 — "마지막 점프"만 떼어내기

작은 값을 손으로 세보면 **1, 2, 3, 5, 8 …** 피보나치가 보인다.

| n | 방법 수 f(n) |
| --- | --- |
| 1 | 1 |
| 2 | 2 |
| 3 | 3 |
| 4 | 5 |
| 5 | 8 |

그런데 *왜* 앞 두 개의 합일까? 핵심은 **마지막 점프 한 번**만 생각하는 것이다.

끝 칸 `n`에 막 도착한 순간, 그 **마지막 점프**는 둘 중 하나일 수밖에 없다.

- **경우 A**: `n-1` 칸에 있다가 **1칸** 뛰어서 도착
- **경우 B**: `n-2` 칸에 있다가 **2칸** 뛰어서 도착

1칸/2칸만 뛸 수 있으니 `n`에 딱 떨어지는 길은 이 둘뿐이고, 둘은 절대 겹치지 않는다(마지막이 1칸이면서 동시에 2칸일 수 없다). 그래서:

```text
f(n) = f(n-1) + f(n-2)
```

`n-1`까지 가는 모든 길 뒤에 "1칸"을, `n-2`까지 가는 모든 길 뒤에 "2칸"을 붙이면 그게 곧 `n`에 도달하는 모든 길이다. 이게 "앞 두 개의 합"의 진짜 이유다.

## 처음 작성했던 코드와 약했던 점

처음엔 점화식만 외워서 변수 2개 동시대입으로 바로 적었다.

```python
def solution(n):
    if n == 1:
        return 1
    if n == 2:
        return 2
    a, b = 1, 2
    for i in range(2, n):
        a, b = b, (a + b) % 1234567   # 이 줄이 왜 안 깨지는지 설명을 못 했다
    return b
```

이 코드 자체는 **정답**이다. 진짜 약점은 코드가 아니라 이해였다.

1. **점화식을 외우기만 했다.** 왜 `f(n-1)+f(n-2)`인지(= 마지막 점프 관점)를 설명하지 못했다.
2. **`a, b = b, a+b` 동시대입을 오해했다.** 위에서부터 순서대로 실행된다고 착각하면 `a`가 먼저 바뀌어 `b` 계산이 틀어진다고 생각하게 된다. 실제로는 **오른쪽 전체를 "지금 값"으로 먼저 계산한 뒤 한꺼번에 대입**한다.

   ```python
   # 만약 두 줄로 쪼개면 버그 (옛날 a를 잃는다)
   a = b          # a가 먼저 b로 덮여버림
   b = a + b      # 여기 a는 이미 바뀐 값 → 틀림
   ```

   `a, b = b, a + b` 한 줄은 옛날 `a`를 잃기 전에 오른쪽 `(b, a+b)`를 통째로 계산하므로 안전하다.
3. **메모 없는 순수 재귀의 함정.** "점화식이니까 그냥 재귀로 짜면 되지" 하면 아래처럼 쓰게 되는데, 이건 같은 값을 어마어마하게 중복 계산해서 `n`이 조금만 커져도 끝나지 않는다.

   ```python
   def f(n):
       if n <= 2:
           return n
       return f(n - 1) + f(n - 2)   # 중복 호출 폭발 → n=2000이면 영원히 안 끝남
   ```

   호출 트리가 피보나치 트리처럼 갈라져서 호출 횟수가 **지수적**으로 늘어난다(아래 복잡도 표 참고). 이게 DP(메모이제이션/표)가 필요한 이유다.

## 개선 풀이 1: dp 표 (bottom-up) — 가장 직관적

`dp[i]`를 **`i`번 칸까지 가는 방법 수**로 정의하면 칸 번호와 답이 1:1로 붙어서 눈으로 따라가기 쉽다. 표를 왼쪽부터 채우고, 새 칸은 "바로 왼쪽 두 칸의 합"으로만 채운다.

```python
def solution(n):
    if n <= 2:
        return n                 # n=1 → 1, n=2 → 2 (표 만들 필요 없음)

    dp = [0] * (n + 1)           # dp[i] = i번 칸까지 가는 방법 수
    dp[1] = 1
    dp[2] = 2

    for i in range(3, n + 1):    # 3번 칸부터 n번 칸까지 차례로 채움
        dp[i] = (dp[i - 1] + dp[i - 2]) % 1234567

    return dp[n]
```

표가 채워지는 모습(`n=5`):

```text
칸:    1   2   3   4   5
      [1] [2] [ ] [ ] [ ]   ← 시작값 두 개
dp[3]=dp[2]+dp[1]=3
      [1] [2] [3] [ ] [ ]
dp[4]=dp[3]+dp[2]=5
      [1] [2] [3] [5] [ ]
dp[5]=dp[4]+dp[3]=8
      [1] [2] [3] [5] [8]   ← return dp[5] = 8
```

새 칸을 채울 때 바로 왼쪽 두 칸만 보면 된다는 게 한눈에 보인다. **처음 배울 때 추천하는 방식.**

## 개선 풀이 2: 변수 2개 (rolling) — 공간을 O(1)로

dp 표를 보면 "어차피 매번 바로 앞 두 칸만 쓴다". 그러면 표 전체를 들고 있을 필요 없이 **앞앞/앞 두 값만** 굴리면 된다. 이게 처음에 외워 썼던 동시대입 버전이고, 표 저장을 버린 만큼 공간이 `O(n)`→`O(1)`로 줄어든다.

```python
def solution(n):
    if n <= 2:
        return n
    a, b = 1, 2                  # a=f(1), b=f(2)
    for _ in range(3, n + 1):
        a, b = b, (a + b) % 1234567   # 창문을 한 칸씩 오른쪽으로 민다
    return b
```

`a, b = b, a+b`는 "앞앞·앞 두 칸을 한 칸씩 밀면서 `다음 = 앞앞 + 앞`을 만드는 것"이다. **사라진 작업**은 dp 표 전체 저장 — 결과는 같지만 메모리를 거의 안 쓴다.

## 개선 풀이 3: 재귀 + 메모이제이션 (top-down) — 점화식을 그대로

점화식을 코드로 직역하고 싶다면, 순수 재귀의 중복 계산만 **메모**로 막으면 된다. 한 번 구한 `f(k)`를 저장해두고 재사용한다.

```python
import sys
from functools import lru_cache

def solution(n):
    sys.setrecursionlimit(3000)   # n=2000까지 재귀 깊이 확보 (기본 1000이라 필요)

    @lru_cache(maxsize=None)
    def f(k):
        if k <= 2:
            return k
        return (f(k - 1) + f(k - 2)) % 1234567

    return f(n)
```

점화식과 코드가 1:1로 닮아 읽기 좋다. 다만 파이썬은 기본 재귀 깊이 제한(약 1000)이 있어 `n=2000`이면 `RecursionError`가 날 수 있으니 `setrecursionlimit`가 필요하다. **이 한 가지 함정 때문에** 실무/제출에선 보통 bottom-up(풀이 1·2)을 더 선호한다.

## 시간 복잡도와 공간 복잡도

여기서 `n`은 **칸의 수(목표 지점)**이고 `1 ≤ n ≤ 2000`이다.

| 풀이 | 시간 복잡도 | 공간 복잡도 | 한 줄 메모 |
| --- | --- | --- | --- |
| 메모 없는 순수 재귀 | `O(φ^n)` (지수) | `O(n)` | 같은 값 중복 호출 폭발 → **사용 불가** |
| 개선 풀이 1: dp 표 | `O(n)` | `O(n)` | 직관적, 표를 눈으로 확인 |
| 개선 풀이 2: 변수 2개 | `O(n)` | `O(1)` | 표 저장을 버려 공간 절약 |
| 개선 풀이 3: 재귀 + 메모 | `O(n)` | `O(n)` | 점화식 그대로, 깊이 제한 주의 |

단계별로 따져보면:

- **메모 없는 순수 재귀 — 왜 터지나.** `f(n)`이 `f(n-1)`과 `f(n-2)`를 부르고, 그 둘이 또 각각 둘을 부른다. 호출 트리가 거의 두 배씩 갈라져서 총 호출 횟수가 대략 `f(n)`에 비례 → 황금비 `φ ≈ 1.618`을 밑으로 하는 **지수** `O(φ^n)`. 입력이 1 늘 때마다 일이 약 1.6배씩 불어난다. `n=2000`이면 천문학적이라 끝나지 않는다. 병목은 **중복 호출** 그 자체다.
- **dp 표 — `O(n)` 시간/공간.** `dp = [0]*(n+1)` 만들기 `O(n)` + `for i in range(3, n+1)`가 `n-2`번 도는데 각 반복은 덧셈·나머지 한 번이라 `O(1)`. 합쳐도 `O(n)`. 표를 끝까지 들고 있으니 공간은 `O(n)`. 병목은 **단일 for 루프**.
- **변수 2개 — 시간은 같고 공간만 `O(1)`.** 루프 횟수(`n-2`번)와 각 반복 비용은 dp 표와 동일하므로 시간은 그대로 `O(n)`. 다만 표 대신 변수 두 개만 유지 → 공간 `O(1)`. dp 표 대비 **사라진 작업 = 전체 표 저장**.
- **재귀 + 메모 — `O(n)`.** 메모 덕분에 `f(1)…f(n)` 각 상태를 딱 한 번씩만 계산(`n`개 × `O(1)`) → 시간 `O(n)`. 메모 딕셔너리와 재귀 호출 스택(깊이 최대 `n`)으로 공간 `O(n)`.
- **best / average / worst.** 이 문제는 입력값에 따른 분기·조기 종료가 없어 어떤 `n`이든 동작이 같다. 따라서 dp/변수 풀이는 best=average=worst 모두 `O(n)`, 순수 재귀는 모두 지수다(정렬·해시처럼 케이스가 갈리지 않는다).
- **제한과 연결.** `n ≤ 2000`이므로 `O(n)`은 최대 약 2000번 연산 → 1초 안에 가뿐히 통과. 반면 `O(φ^2000)`은 우주가 끝나도 못 끝낸다. 그래서 점화식이 보이는 순간 **반드시 메모/표(DP)로** 중복 계산을 없애야 한다.

## 이번 문제에서 배운 점

- 점화식은 **"마지막 한 수(여기선 마지막 점프)"**를 어떻게 갈라낼지 생각하면 자연스럽게 유도된다. 외우는 게 아니라 세우는 것.
- `a, b = b, a + b` 같은 **동시대입은 오른쪽을 먼저 통째로 계산**한다. 순서대로 실행된다는 착각이 깨지는 지점.
- 같은 점화식이라도 **bottom-up 표 / rolling 변수 / top-down 메모** 세 가지로 풀 수 있고, 시간은 모두 `O(n)`이지만 공간과 가독성·함정(재귀 깊이)이 다르다. 이해엔 표, 메모리엔 변수 2개.
- "점화식 = 그냥 재귀" 가 아니다. **메모가 빠진 재귀는 지수 폭발**한다 — DP가 존재하는 이유를 몸으로 이해했다.
