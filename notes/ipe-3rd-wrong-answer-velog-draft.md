# 정보처리기사 필기 3회차 오답노트: 헷갈린 용어를 다시 내 말로 정리하기

> 3회차 기출을 풀고 틀린 문제를 다시 정리했다.  
> 이번에도 목표는 정답 번호를 외우는 것이 아니라, 비슷한 보기 사이에서 왜 그 답이 되는지 설명할 수 있게 만드는 것이다.

---

## 이번 오답에서 보인 패턴

이번 회차는 단순 암기보다 **용어의 역할 구분**이 많이 흔들렸다.

- 설계 방법의 방향을 헷갈린 문제  
  예: 하향식 설계, 상향식 설계, 아키텍처 설계 절차
- UI/설계/테스트 도구의 이름을 구분해야 하는 문제  
  예: 목업, 디자인 패턴, N-S Chart, 화이트박스 테스트, 코드 인스펙션
- 데이터베이스 개념에서 핵심 단어 하나를 잡아야 하는 문제  
  예: 전칭 기호 `∀`, 이행적 종속, `REVOKE`
- 운영체제와 네트워크에서 역할을 구분해야 하는 문제  
  예: ICMP, 세마포어, Best Fit, 쉘과 커널, DAS
- 프로젝트 관리와 보안 용어를 정확히 기억해야 하는 문제  
  예: 간트 차트, `wtmp`, DPI, 테일러링

그래서 아래 정리는 문제 문장을 그대로 옮기기보다, 내가 다시 헷갈리지 않도록 **정답 포인트와 구분 기준**을 중심으로 정리했다.

## 1과목 소프트웨어 설계

### 5번. 하향식 설계와 상향식 설계

**정답 포인트: 상향식 설계에서는 인터페이스가 이미 성립되어 있어야 기능 추가가 쉽다.**

하향식 설계와 상향식 설계는 설계를 시작하는 방향이 다르다.

| 구분 | 설계 방향 | 초보자식 이해 |
| --- | --- | --- |
| 하향식 설계 | 전체 구조에서 세부 모듈로 내려감 | 큰 그림을 먼저 잡고 작은 기능으로 쪼갬 |
| 상향식 설계 | 하위 모듈에서 상위 구조로 올라감 | 작은 부품을 먼저 만들고 조립함 |

상향식 설계는 하위 모듈들을 먼저 만든 뒤 결합하는 방식이다. 그래서 모듈끼리 어떻게 연결될지, 즉 **인터페이스가 잘 맞아야** 나중에 기능을 추가하거나 결합하기 쉽다.

내가 조심해야 할 표현은 “인터페이스가 이미 성립되어 있지 않더라도 기능 추가가 쉽다”이다. 이 말은 반대로 봐야 한다. 상향식 설계에서는 만들어 둔 하위 모듈을 조립해야 하므로 인터페이스가 중요하다.

### 9번. UI 설계 도구: 목업

**정답 포인트: 실제 동작보다는 화면의 모양을 정적으로 보여주는 것은 목업(Mockup)이다.**

UI 설계 도구 이름은 서로 비슷해서 헷갈리기 쉽다.

| 도구 | 핵심 |
| --- | --- |
| 스토리보드 | 화면 흐름, 화면 간 이동, 설명을 문서처럼 정리 |
| 목업 | 실제 구현 전 화면 모양을 정적으로 표현 |
| 프로토타입 | 일부 동작을 넣어 사용 흐름을 시험 |
| 유스케이스 | 사용자가 시스템으로 무엇을 하는지 표현 |

목업은 “이 화면이 대략 이렇게 생길 것이다”를 보여주는 데 가깝다. 버튼을 눌렀을 때 실제로 동작하는지보다, 화면 배치와 구성 요소를 확인하는 목적이 크다.

### 15번. 아키텍처 설계 과정

**정답 포인트: 설계 목표 설정 → 시스템 타입 결정 → 아키텍처 패턴 적용 → 서브시스템 구체화 → 설계 검토 순서다.**

아키텍처 설계는 바로 세부 모듈부터 만드는 것이 아니라, 목표와 큰 구조를 먼저 정한다.

```text
설계 목표 설정
-> 시스템 타입 결정
-> 아키텍처 패턴/스타일 적용
-> 서브시스템 구체화
-> 설계 검토
```

순서 문제에서는 “큰 방향을 먼저 정하고, 점점 구체화한 뒤, 마지막에 검토한다”는 흐름으로 기억하면 덜 흔들린다.

### 17번. 디자인 패턴

**정답 포인트: 소프트웨어 설계에서 반복적으로 발생하는 문제에 대한 일반적인 해결 방법은 디자인 패턴이다.**

디자인 패턴은 특정 코드 한 줄을 외우는 것이 아니라, 자주 반복되는 설계 문제에 대한 검증된 해결 방식이다.

예를 들어 객체 생성을 유연하게 하고 싶을 때 Factory Method, 객체 상태 변화에 따라 알림을 보내고 싶을 때 Observer 같은 패턴을 떠올릴 수 있다.

시험에서는 “일반적이고 반복적인 해결 방법”이라는 표현이 나오면 디자인 패턴을 먼저 떠올리면 된다.

### 19번. FEP

**정답 포인트: 입력 데이터를 주 프로세서가 처리하기 전에 미리 처리하는 것은 FEP이다.**

`FEP`는 `Front End Processor`의 약자다. 이름 그대로 앞단에서 먼저 처리하는 장치나 프로그램이다.

초보자식으로 보면, 메인 프로세서에게 모든 일을 바로 넘기기 전에 앞에서 데이터를 정리해 주는 역할이다. 이렇게 하면 주 프로세서가 처리해야 할 부담을 줄일 수 있다.

## 2과목 소프트웨어 개발

### 34번. N-S Chart

**정답 포인트: N-S Chart는 화살표나 GOTO를 사용하지 않는다.**

N-S Chart는 구조적 프로그램 설계를 표현하는 도구다. 핵심은 프로그램 논리를 **연속, 선택, 반복** 구조로 깔끔하게 표현하는 것이다.

| 특징 | 설명 |
| --- | --- |
| 논리 중심 | 처리 흐름의 논리를 도형으로 표현 |
| 코드 변환 용이 | 구조가 명확해서 코드로 옮기기 좋음 |
| GOTO 미사용 | 복잡한 점프 흐름을 피함 |
| 제어 구조 표현 | 연속, 선택, 반복 구조를 나타냄 |

그래서 “화살표나 GOTO를 사용하여 이해하기 쉽다”는 설명은 틀린 설명이다. N-S Chart는 오히려 그런 복잡한 이동을 줄이기 위한 구조적 표현에 가깝다.

### 37번. 화이트박스 테스트

**정답 포인트: 데이터 흐름 검사와 루프 검사는 화이트박스 테스트에 해당한다.**

화이트박스 테스트는 프로그램 내부 구조를 보고 검사하는 방식이다. 코드의 흐름, 조건, 반복문, 데이터 사용 과정을 확인한다.

| 테스트 관점 | 보는 것 |
| --- | --- |
| 화이트박스 테스트 | 내부 로직, 제어 흐름, 데이터 흐름 |
| 블랙박스 테스트 | 입력과 출력, 기능의 결과 |

데이터 흐름 검사는 변수가 정의되고 사용되는 흐름을 본다. 루프 검사는 반복문이 제대로 동작하는지 본다. 둘 다 코드 내부 구조를 알아야 하므로 화이트박스 테스트다.

### 39번. 코드 인스펙션

**정답 포인트: 코드 인스펙션은 동적 테스트가 아니라 정적 테스트에 가깝다.**

코드 인스펙션은 프로그램을 실행해 보는 것이 아니라, 코드를 읽고 결함을 찾는 활동이다.

확인할 수 있는 것들은 다음과 같다.

- 결함 가능성
- 코딩 표준 준수 여부
- 코드 품질
- 효율성이나 유지보수성 문제

즉 “동적 테스트 시에만 활용한다”는 설명이 틀렸다. 동적 테스트는 프로그램을 실제로 실행하면서 확인하는 방식이고, 코드 인스펙션은 실행 전에도 할 수 있는 정적 테스트다.

## 3과목 데이터베이스 구축

### 46번. 관계해석의 전칭 기호

**정답 포인트: ‘모든 것에 대하여’를 의미하는 기호는 `∀`이다.**

관계해석에서 논리 기호는 의미를 정확히 기억해야 한다.

| 기호 | 의미 |
| --- | --- |
| `∃` | 존재한다 |
| `∈` | 원소이다, 포함된다 |
| `∀` | 모든 것에 대하여 |
| `⊂` | 부분집합 |

`∀`는 영어로 `For All`이라고 생각하면 외우기 쉽다. “모든 학생에 대해”, “모든 튜플에 대해”처럼 전체 대상을 조건으로 묶을 때 쓰인다.

### 50번. 이행적 종속과 3NF

**정답 포인트: `A -> B`, `B -> C`일 때 `A -> C`가 되는 이행적 종속은 2NF에서 3NF로 가는 과정에서 제거한다.**

정규화 단계는 어떤 종속성을 제거하는지로 기억하면 좋다.

| 단계 | 핵심 |
| --- | --- |
| 1NF | 반복 속성 제거, 원자값으로 정리 |
| 2NF | 부분 함수 종속 제거 |
| 3NF | 이행적 함수 종속 제거 |
| BCNF | 모든 결정자가 후보키가 되도록 정리 |

이행적 종속은 중간 속성을 거쳐 다른 속성이 결정되는 상황이다.

```text
A -> B
B -> C
그러면 A -> C
```

예를 들어 학번으로 학과를 알 수 있고, 학과로 학과 사무실을 알 수 있다면, 학번으로 학과 사무실까지 알 수 있게 된다. 이런 간접 의존을 줄이는 단계가 3NF다.

### 52번. SQL의 REVOKE

**정답 포인트: `REVOKE`는 열 이름을 다시 부여하는 명령이 아니라 권한을 취소하는 명령이다.**

SQL 명령은 역할별로 나누어 기억하면 좋다.

| 분류 | 예시 | 역할 |
| --- | --- | --- |
| DDL | `CREATE`, `ALTER`, `DROP` | 테이블, 뷰, 인덱스 같은 구조 정의 |
| DML | `SELECT`, `INSERT`, `UPDATE`, `DELETE` | 데이터 조회와 조작 |
| DCL | `GRANT`, `REVOKE` | 권한 부여와 회수 |

`GRANT`는 권한을 주는 명령이고, `REVOKE`는 이미 준 권한을 취소하는 명령이다. 열 이름을 다시 붙이는 기능과는 관련이 없다.

## 4과목 프로그래밍 언어 활용

### 67번. ICMP

**정답 포인트: IP 전송 중 오류 정보를 보내는 프로토콜은 ICMP이다.**

`ICMP`는 `Internet Control Message Protocol`의 약자다. IP 통신 중에 문제가 생겼을 때 오류나 제어 메시지를 전달하는 역할을 한다.

예를 들어 목적지에 도달할 수 없거나, 경로상에서 문제가 생겼을 때 관련 정보를 알려주는 데 사용된다.

| 프로토콜 | 역할 |
| --- | --- |
| ARP | IP 주소를 MAC 주소로 변환 |
| ICMP | 오류와 제어 메시지 전달 |
| PPP | 점대점 링크에서 데이터 전송 |

문제에서 “IP 동작 과정에서 전송 오류에 대비해 오류 정보를 전송”이라는 표현이 나오면 ICMP를 떠올리면 된다.

### 69번. 세마포어

**정답 포인트: 임계 구역 접근을 제어하는 대표적인 상호 배제 기법은 세마포어이다.**

세마포어는 여러 프로세스나 스레드가 공유 자원에 동시에 접근하지 못하도록 조절하는 도구다.

핵심 동작은 보통 `P` 연산과 `V` 연산으로 설명한다.

| 연산 | 의미 |
| --- | --- |
| P 연산 | 자원을 사용하기 전에 세마포어 값을 감소시키고, 필요하면 기다림 |
| V 연산 | 자원 사용이 끝난 뒤 세마포어 값을 증가시키고, 기다리는 작업을 깨움 |

초보자식으로 보면 세마포어는 “입장권 개수”처럼 생각할 수 있다. 입장권이 남아 있으면 임계 구역에 들어가고, 없으면 기다린다.

### 71번. Best Fit과 내부 단편화

**정답 포인트: 17KB 프로그램은 20KB 공간에 들어가므로 내부 단편화는 3KB이다.**

Best Fit은 들어갈 수 있는 빈 공간 중에서 **가장 작게 남는 공간**을 고르는 배치 전략이다.

빈 공간이 다음과 같다고 하자.

```text
20KB, 16KB, 8KB, 40KB
```

17KB 프로그램은 16KB와 8KB에는 들어갈 수 없다. 20KB와 40KB에는 들어갈 수 있는데, Best Fit은 그중 더 작은 20KB를 고른다.

```text
20KB - 17KB = 3KB
```

따라서 내부 단편화는 `3KB`다.

### 72번. C언어 while과 break

**정답 포인트: 반복문은 `i`가 4가 되었을 때 `break`로 종료되므로 출력은 `i = 4`이다.**

문제의 코드는 `while (1)`로 무한 반복을 만들고, 반복 안에서 `i == 4`가 되면 `break`로 빠져나오는 구조다.

```c
#include <stdio.h>

int main(void) {
    int i = 0;

    while (1) {
        if (i == 4) {
            break; // i가 4이면 반복문 종료
        }
        ++i; // i를 1씩 증가
    }

    printf("i = %d", i);
    return 0;
}
```

흐름을 손으로 따라가면 다음과 같다.

```text
i = 0 -> 1 -> 2 -> 3 -> 4
```

`i`가 4가 된 다음 반복에서 조건문을 만나고, 바로 `break`로 빠져나간다. 그래서 출력값은 `i = 4`다.

### 80번. UNIX 쉘과 커널

**정답 포인트: 프로세스와 메모리를 관리하는 것은 쉘이 아니라 커널의 기능이다.**

쉘은 사용자가 입력한 명령을 해석해서 커널에 전달하는 인터페이스 역할을 한다.

| 구분 | 역할 |
| --- | --- |
| 쉘 | 명령 해석, 스크립트 실행, 사용자 환경 설정 |
| 커널 | 프로세스 관리, 메모리 관리, 파일 시스템, 장치 제어 |

쉘도 스크립트처럼 반복 명령을 작성할 수 있고, 초기화 파일로 사용자 환경을 설정할 수 있다. 하지만 실제 프로세스와 메모리를 직접 관리하는 핵심은 커널이다.

### 84번. DAS

**정답 포인트: 서버나 컴퓨터에 직접 연결되는 스토리지는 DAS이다.**

`DAS`는 `Direct Attached Storage`의 약자다. 이름처럼 저장 장치가 서버나 컴퓨터에 직접 붙어 있는 구조다.

| 스토리지 | 특징 |
| --- | --- |
| DAS | 서버에 직접 연결 |
| NAS | 네트워크를 통해 파일 단위로 접근 |
| SAN | 전용 네트워크를 통해 블록 단위로 접근 |

문제 지문에서 “직접 연결”이라는 느낌이 강하면 DAS를 떠올리면 된다.

## 5과목 정보시스템 구축 관리

### 91번. 간트 차트

**정답 포인트: 간트 차트의 수평 막대 길이는 인원수가 아니라 작업 기간을 나타낸다.**

간트 차트는 프로젝트 작업이 언제 시작해서 언제 끝나는지 한눈에 보여주는 일정 관리 도구다.

| 요소 | 의미 |
| --- | --- |
| 작업 목록 | 프로젝트를 구성하는 세부 작업 |
| 수평 막대 | 각 작업의 기간 |
| 막대 위치 | 시작 시점과 종료 시점 |

그래서 수평 막대의 길이를 “작업에 필요한 인원수”라고 하면 틀리다. 막대가 길수록 더 오래 걸리는 작업이라는 뜻이다.

### 97번. wtmp 로그

**정답 포인트: 사용자 로그인, 로그아웃, 시스템 부팅 같은 기록을 담는 로그 파일은 `wtmp`이다.**

UNIX/Linux 계열 시스템의 로그 파일은 이름이 짧아서 헷갈리기 쉽다.

`wtmp`는 로그인과 로그아웃 기록, 시스템 부팅 기록 등을 확인할 때 등장하는 파일이다. 보통 `last` 명령이 이 파일을 참조해서 접속 이력을 보여준다.

시험에서는 “로그인/로그아웃 기록”과 `wtmp`를 묶어서 기억해 두면 좋다.

### 99번. DPI

**정답 포인트: 패킷 내부 콘텐츠까지 분석하는 기술은 DPI이다.**

`DPI`는 `Deep Packet Inspection`의 약자다. 단순히 출발지와 목적지 같은 헤더만 보는 것이 아니라, 패킷 내부의 내용까지 깊게 검사하는 기술이다.

활용 목적은 다음과 같다.

- 침입 시도 탐지
- 악성 트래픽 분석
- 트래픽 제어
- 보안 정책 적용

문제에서 “OSI 7계층”, “패킷 내부 콘텐츠”, “침입 탐지”, “트래픽 조정” 같은 표현이 함께 나오면 DPI를 떠올리면 된다.

### 100번. 소프트웨어 개발 방법론 테일러링

**정답 포인트: 테일러링은 예상되는 변화를 배제하는 것이 아니라, 프로젝트 특성에 맞게 방법론을 조정하는 활동이다.**

테일러링은 기존 개발 방법론을 프로젝트 상황에 맞게 조정하는 것이다.

예를 들어 프로젝트 규모가 작다면 산출물을 줄일 수 있고, 보안 요구사항이 강하다면 검토 절차를 더 강화할 수 있다.

| 관점 | 목적 |
| --- | --- |
| 관리적 측면 | 위험을 미리 식별하고 안정적으로 진행 |
| 기술적 측면 | 프로젝트에 맞는 기법과 도구 선택 |

따라서 “예상되는 변화를 배제하고 신속히 진행한다”는 설명은 틀렸다. 테일러링은 오히려 변화와 프로젝트 특성을 고려해서 절차와 산출물을 조정하는 활동이다.

## 한 번 더 묶어서 외울 것들

### 1. 설계와 개발 도구

- 상향식 설계는 하위 모듈을 조립하므로 인터페이스가 중요하다.
- 목업은 정적인 화면 모양 확인에 가깝다.
- 디자인 패턴은 반복되는 설계 문제에 대한 일반적인 해결 방법이다.
- N-S Chart는 GOTO나 화살표를 쓰지 않는 구조적 표현이다.

### 2. 테스트 용어

- 화이트박스 테스트는 내부 구조를 보고 검사한다.
- 데이터 흐름 검사와 루프 검사는 화이트박스 테스트다.
- 코드 인스펙션은 실행하지 않고 코드를 읽으며 확인하는 정적 테스트다.

### 3. 데이터베이스와 SQL

- `∀`는 “모든 것에 대하여”이다.
- 이행적 종속 제거는 2NF에서 3NF로 가는 과정이다.
- `GRANT`는 권한 부여, `REVOKE`는 권한 취소다.

### 4. 운영체제와 네트워크

- ICMP는 IP 통신 중 오류와 제어 메시지를 전달한다.
- 세마포어는 임계 구역 접근을 제어한다.
- Best Fit은 들어갈 수 있는 공간 중 가장 작은 공간을 고른다.
- 프로세스와 메모리 관리는 쉘이 아니라 커널의 역할이다.

### 5. 정보시스템 구축 관리

- 간트 차트의 막대 길이는 작업 기간이다.
- `wtmp`는 로그인/로그아웃 기록과 관련 있다.
- DPI는 패킷 내부 콘텐츠까지 깊게 검사한다.
- 테일러링은 프로젝트 특성에 맞게 방법론을 조정하는 것이다.
