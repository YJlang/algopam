# 귀찮아서 만든 Velog 자동 포스팅 Custom Skill 회고

요즘 공부한 내용이나 프로젝트 기록을 Velog에 정리하려고 하면, 이상하게 글을 쓰기 전 단계에서 먼저 지친다.  
분명 내용은 머릿속에 있고, 코드도 있고, 정리할 소재도 있는데 매번 글 구조를 잡고, 제목을 정하고, Markdown으로 다듬고, Velog 에디터에 옮기는 과정이 은근히 번거로웠다.

그래서 이번에는 그 번거로움 자체를 줄여보기로 했다.  
결과물은 Codex에서 사용할 수 있는 `velog-auto-posting` Custom Skill이다. 사용자가 어떤 주제로 Velog 글을 요청하면, Agent가 자료를 읽고, 글의 방향을 잡고, Markdown 초안을 저장한 뒤, 필요하면 Velog에 초안으로 올리는 흐름까지 도와주는 Skill이다.

## 만들게 된 이유: 시작은 귀차니즘이었다

솔직히 말하면 거창한 문제의식에서 시작한 건 아니었다.  
가장 큰 이유는 그냥 귀찮음이었다.

Velog에 글 하나를 올리려면 생각보다 손이 많이 간다.

- 오늘 정리할 주제를 정한다.
- 관련 파일이나 코드를 다시 읽는다.
- 글의 흐름을 잡는다.
- 제목과 소제목을 다듬는다.
- Markdown으로 정리한다.
- Velog 에디터에 붙여 넣고 깨진 부분이 없는지 확인한다.
- 발행 전에는 혹시 민감한 내용이나 틀린 설명이 없는지도 다시 본다.

각 단계가 엄청 어렵지는 않다.  
문제는 매번 반복된다는 점이었다.

특히 알고리즘 풀이 글이나 공부 회고처럼 구조가 어느 정도 반복되는 글은 더 그랬다.  
내가 하고 싶은 건 “이번에 뭘 배웠는지”를 남기는 일인데, 실제로는 “어떤 섹션부터 써야 하지?”, “코드 설명은 어디까지 해야 하지?”, “Velog에 붙여 넣을 때 한글 안 깨지나?” 같은 자잘한 작업에 에너지가 많이 쓰였다.

그래서 생각했다.

> 이 반복 작업을 Agent에게 맡길 수 있지 않을까?

## AI Agent 자동화에서 얻은 영감

요즘 AI Agent를 활용해서 업무를 자동화하는 사례를 자주 보게 된다.  
단순히 질문에 답하는 챗봇이 아니라, 파일을 읽고, 필요한 정보를 조사하고, 결과물을 만들고, 브라우저까지 조작하는 방식이다.

이 흐름을 보면서 꽤 인상 깊었던 점은 “AI를 하나의 실행자처럼 다룰 수 있다”는 것이었다.

예전에는 AI에게 글을 부탁하면 보통 이런 식이었다.

> 이 주제로 글 써줘.

그러면 결과는 그럴듯할 수 있지만, 실제 내 프로젝트와 연결되지는 않는 경우가 많았다.  
내 코드나 파일을 직접 읽은 것도 아니고, 내가 왜 이걸 만들었는지도 모른 채 일반적인 글을 만들어내기 때문이다.

반대로 Agent 방식은 조금 다르다.

- 먼저 로컬 파일을 읽는다.
- 사용자가 준 맥락을 기준으로 글의 목적을 잡는다.
- 필요한 경우 웹에서 사실을 확인한다.
- 로컬 Markdown 백업을 만든다.
- 사용자가 원하면 브라우저로 Velog에 들어가 초안까지 저장한다.

즉, “글 작성”이라는 하나의 작업을 여러 단계로 나누고, 그 단계를 Agent가 차례대로 수행하게 만들 수 있다.  
이게 내가 Custom Skill을 만들게 된 직접적인 계기였다.

## 만든 것: `velog-auto-posting`

이번에 만든 Skill의 이름은 `velog-auto-posting`이다.

처음에는 알고리즘 문제 풀이 글을 Velog 초안으로 만드는 용도에 가까웠다.  
예를 들어 BOJ 문제 풀이 코드를 읽고, 공식 문제 페이지를 확인하고, 원래 코드의 의도와 개선 풀이를 정리하는 식이었다.

그런데 사용하다 보니 굳이 알고리즘 글에만 묶어둘 필요가 없겠다는 생각이 들었다.  
Velog에 올리는 글은 알고리즘 풀이만 있는 게 아니다.

- 공부 정리
- 프로젝트 회고
- 기술 튜토리얼
- 개발 로그
- 비교/리뷰 글
- 자료 조사 요약

이런 글들도 결국 공통 흐름이 있다.  
자료를 읽고, 글의 목적을 정하고, 구조를 잡고, 초안을 만들고, 필요하면 Velog에 올리는 것이다.

그래서 기존 Skill을 범용 Velog 자동 포스팅 Skill로 업그레이드했다.

## Skill의 핵심 흐름

`velog-auto-posting` Skill이 따르는 기본 흐름은 대략 이렇다.

1. 사용자가 어떤 내용을 포스팅하고 싶은지 파악한다.
2. 사용자가 제공한 파일, 코드, 링크, 메모를 먼저 읽는다.
3. 외부 사실이 필요하면 공식 문서나 신뢰할 수 있는 자료로 확인한다.
4. 글의 유형에 맞는 구조를 선택한다.
5. 한국어 Velog 스타일에 맞게 Markdown 초안을 작성한다.
6. 로컬에 `.md` 백업 파일을 저장한다.
7. 사용자가 요청하면 Playwright로 Velog에 접속해 초안으로 저장한다.

여기서 중요하게 생각한 점은 “바로 Velog에 쓰기”보다 “먼저 로컬 Markdown을 남기기”였다.  
웹 에디터에서만 작업하면 나중에 수정하거나 재사용하기 어렵다. 반면 로컬 파일이 있으면 내가 다시 읽고 고치기도 쉽고, 같은 구조를 다음 글에도 활용할 수 있다.

## 디렉토리 구조

현재 Skill은 아래와 같은 구조로 되어 있다.

```text
skills/velog-auto-posting/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── assets/
│   └── velog-post-template.md
└── references/
    └── openai-principles.md
```

각 파일의 역할은 다음과 같다.

### `SKILL.md`

Skill의 중심이 되는 파일이다.  
어떤 상황에서 이 Skill을 써야 하는지, Agent가 어떤 순서로 작업해야 하는지, Velog에 올릴 때 어떤 규칙을 지켜야 하는지가 들어 있다.

특히 아래 내용을 중요하게 넣었다.

- 사용자의 자료를 먼저 읽고 글을 쓸 것
- 필요한 사실은 확인하고 쓸 것
- 한국어 Velog 톤으로 작성할 것
- 글의 유형에 따라 구조를 다르게 잡을 것
- 로컬 Markdown 백업을 먼저 만들 것
- Velog에는 기본적으로 초안 저장만 할 것
- 명시적으로 요청받은 경우에만 발행할 것

자동화라고 해서 무조건 바로 공개까지 가는 것은 위험하다고 생각했다.  
그래서 “초안 저장이 기본값, 발행은 명시적 요청이 있을 때만”이라는 규칙을 넣었다.

### `agents/openai.yaml`

Codex에서 이 Skill이 어떻게 표시될지 정하는 메타데이터 파일이다.

```yaml
interface:
  display_name: "Velog Auto Posting"
  short_description: "Draft and stage polished Velog posts"
  default_prompt: "Use $velog-auto-posting to prepare a polished Velog draft from my topic or source material, save a local markdown backup, and stage it on Velog if requested."

policy:
  allow_implicit_invocation: true
```

여기서 `allow_implicit_invocation: true`를 둔 이유는, 사용자가 매번 Skill 이름을 정확히 말하지 않아도 Velog 포스팅 요청이라면 자연스럽게 이 Skill을 떠올릴 수 있게 하기 위해서다.

### `assets/velog-post-template.md`

Velog 글 초안을 만들 때 참고하는 기본 템플릿이다.

처음에는 BOJ 알고리즘 풀이 전용 템플릿에 가까웠지만, 지금은 어떤 주제에도 적용할 수 있도록 더 느슨한 구조로 바꿨다.

```md
# {{title}}

{{intro_paragraph}}

{{source_links_section}}

## 글의 목표

## 배경

## 핵심 정리

## 자세히 보기

## 예시

## 헷갈렸던 점 / 주의할 점

## 정리

## 다음에 해볼 것
```

템플릿은 정답지가 아니라 출발점이라고 생각했다.  
글의 종류에 따라 섹션은 줄어들 수도 있고, 이름이 바뀔 수도 있다. 중요한 건 매번 빈 화면에서 시작하지 않아도 된다는 점이다.

### `references/openai-principles.md`

이 파일은 Skill을 왜 이런 구조로 만들었는지에 대한 참고 문서다.  
Agent가 파일을 읽고, 필요한 사실을 확인하고, 로컬 결과물을 남기고, 사용자가 요청한 경우에만 브라우저 자동화를 수행한다는 원칙을 정리해두었다.

실제 포스팅 작업을 할 때 항상 읽어야 하는 파일은 아니고, Skill 자체를 개선할 때 참고하는 쪽에 가깝다.

## 만들면서 신경 쓴 점

가장 신경 쓴 부분은 “자동화의 범위”였다.

글을 자동으로 쓰고 Velog에 올리는 건 편하지만, 너무 쉽게 공개까지 이어지면 위험할 수 있다.  
잘못된 정보가 들어갈 수도 있고, 개인적인 내용이나 민감한 정보가 그대로 들어갈 수도 있다.

그래서 Skill 안에 몇 가지 안전장치를 넣었다.

- 사용자가 준 파일과 맥락을 먼저 확인한다.
- 외부 사실은 필요할 때 검증한다.
- 긴 원문은 그대로 복사하지 않고 재정리한다.
- 비공개 정보나 토큰, 민감한 링크는 제외한다.
- Velog 작업은 기본적으로 초안 저장까지만 한다.
- 발행은 사용자가 명시적으로 요청했을 때만 한다.

자동화는 손을 덜어주는 도구이지, 판단을 완전히 없애는 도구는 아니라고 생각한다.  
그래서 마지막 공개 버튼만큼은 사용자의 의도를 분명히 확인하는 쪽이 맞다고 봤다.

## 이번에 배운 점

이번 Custom Skill을 만들면서 느낀 점은, AI Agent 자동화의 핵심이 “프롬프트를 길게 쓰는 것”만은 아니라는 것이다.

더 중요한 건 반복되는 작업을 잘게 나누고, 그 순서를 안정적으로 정하는 일이었다.

- 먼저 무엇을 읽어야 하는가
- 어떤 경우에 웹 검색이 필요한가
- 어떤 형식으로 결과물을 남겨야 하는가
- 언제 브라우저 자동화를 써야 하는가
- 어디까지 자동화하고 어디서 멈춰야 하는가

이런 기준이 있어야 Agent가 매번 비슷한 품질로 움직일 수 있다.

또 하나 좋았던 점은, 내가 귀찮아하던 일을 자세히 들여다보니 오히려 좋은 자동화 주제가 되었다는 것이다.  
귀찮음은 그냥 게으름의 문제가 아니라, 반복 작업이 숨어 있다는 신호일 때가 많다.

이번에는 그 신호를 따라가서 작은 Skill 하나를 만들었고, 앞으로 Velog 글을 쓸 때마다 이 Skill을 계속 개선해볼 생각이다.

## 정리

이번 작업은 “Velog 글 쓰기 귀찮다”에서 시작했다.  
하지만 막상 만들고 보니 단순한 글쓰기 도우미라기보다, 내가 공부하고 만든 것들을 꾸준히 기록하기 위한 작은 자동화 파이프라인에 가까워졌다.

`velog-auto-posting` Skill은 앞으로 이런 일을 맡게 된다.

- 주제와 자료를 바탕으로 글의 방향을 잡기
- Markdown 초안을 만들기
- 로컬 백업을 남기기
- 필요하면 Velog에 초안으로 올리기

아직 완벽한 자동 포스팅 시스템은 아니지만, 적어도 “빈 화면 앞에서 멈추는 시간”은 확실히 줄여줄 수 있을 것 같다.

그리고 무엇보다 마음에 드는 점은, 이 글 자체도 이 Skill을 이용해 작성했다는 것이다.  
도구를 만들고, 그 도구로 도구를 만든 과정을 기록하는 일. 꽤 재미있는 출발점이 된 것 같다.
